# ProxyChoicePro 1.1.3

[en](Guide-en.md) · [ru](Guide-ru.md) · [fr](Guide-fr.md) · [de](Guide-de.md) · [es](Guide-es.md) · [zh](Guide-zh.md)

Два режима подключения: выбранные приложения через SOCKS5/HTTP/HTTPS или доступ к рабочей сети через WireGuard с обычным удалённым рабочим столом Windows. Добавлены адаптивные вкладки, ночной режим, диагностика, избранные ПК и автоматическое восстановление соединения.

Быстрый запуск: откройте ProxyChoicePro.exe или установите ProxyChoicePro-Setup.exe. Выберите «Рабочая сеть», импортируйте клиентский WireGuard .conf для этого ноутбука и нажмите «Подключить». Во вкладке «Компьютеры» добавьте IP рабочего ПК и нажмите «Открыть RDP». Если домашняя и рабочая подсети совпадают, используйте маршруты отдельных ПК /32 и доступный TCP-адрес проверки. Нужен именно клиентский профиль: роутер должен знать открытый ключ этого клиента и разрешать доступ в рабочую LAN. См. руководство по Keenetic.

## 1. Какой трафик идёт через прокси

При подключении приложения с галочкой идут через выбранный прокси. Остальные используют провайдера. ProxyChoicePro всегда отправляет свои интернет-соединения и проверки IP через прокси. Адреса локальной сети остаются прямыми, включая модем LOCAL_ROUTER_IP. Кнопка «Отключить прокси» возвращает обычное подключение всем приложениям. Это выбор маршрута приложений через TUN-интерфейс. Постоянного VPN и блокировки сети после выхода нет: при закрытии программы или остановке движка Windows возвращается к провайдеру.

## 2. Подключение и проверка IP

В режиме «Прокси» выберите SOCKS5, HTTP или HTTPS по данным поставщика. Введите сервер без приставки URL, затем порт и необходимые учётные данные. «Проверить прокси» проверяет доступ без изменения маршрутов Windows. «Подключить» запрашивает права администратора для TUN-интерфейса и проверяет выбранное соединение. «Проверить IP» показывает внешний адрес проверочного соединения, а не результат проверки каждого приложения. Весь значок на панели задач и в трее серый при отключении, жёлтый при подключении, зелёный после успешной проверки соединения и красный при ошибке доступа. Для рабочей сети используйте WireGuard; см. раздел 10.

## 3. Chrome, Edge и YouTube

Поставьте галочки и нажмите «Применить». При активном подключении туннель переподключится. Перезапустите затронутые приложения, чтобы закрыть соединения, созданные до изменения. «Из запущенных» позволяет выбрать несколько программ с Ctrl, а «Выбрать .exe» — добавить закрытую программу. Браузеры используют общий сетевой процесс для всех вкладок: выбор Chrome или Edge отправляет через прокси все сайты этого браузера. Установленный YouTube добавляется и включается при первом запуске, если найден. Браузерное приложение YouTube использует файл своего браузера: YouTube и этот браузер имеют общую галочку. Отдельного правила сайта YouTube нет.

## 4. Microsoft Store

Microsoft Store включён по умолчанию, его можно убрать. Правила охватывают WinStore.App.exe / WinStore.exe и известные адреса каталога, лицензирования, входа и загрузок Microsoft, которыми пользуются службы Windows. Общие адреса входа Microsoft и Windows Update тоже могут идти через прокси, пока эта галочка включена. Все процессы svchost.exe через прокси не отправляются. Загрузки сторонних Win32-приложений из Store могут идти с серверов издателей за пределами списка Microsoft: для них может понадобиться добавить фактическую программу загрузки. После применения изменений перезапустите Store.

## 5. Несколько прокси и сохранение паролей

Добавляйте, переименовывайте и сохраняйте нужные профили. Для перехода на другой прокси сначала отключитесь. Выбор приложений, Store, UDP и язык общие для всех профилей. «Запомнить пароль» сохраняет его в шифрованном виде Windows DPAPI для текущего пользователя Windows; файл не расшифруется у другого пользователя или на другом компьютере. Снимите галочку, если пароль профиля сохранять не нужно. При первом запуске могут импортироваться адреса прокси из ProxyFlow, но прежние исключения не превращаются в выбранные приложения. Папки настроек у программ разные.

## 6. Сеть, DNS и UDP

Поддерживаются IPv4 и IPv6. IP сервера прокси определяется до запуска туннеля. Для DNS внутри туннеля используются виртуальные IP, чтобы правило следовало приложению даже при разрешении имён службой Windows. Общее разрешение DNS идёт через Cloudflare DoH по прокси; прямые соединения используют DNS активного адаптера, а при его отсутствии — прямой DoH. Поэтому служебные DNS-запросы могут проходить через прокси и для приложений без галочки. Локальные IP остаются прямыми. UDP у выбранных приложений по умолчанию выключен: браузерный QUIC сможет перейти на TCP. Разрешайте UDP только при поддержке сервером SOCKS5. HTTP/HTTPS не передают UDP. Неподдерживаемые UDP и ICMP блокируются только на выбранных маршрутах, остальные приложения сохраняют прямой доступ.

## 7. Отключение, выход и сбои

«Отключить прокси» останавливает принадлежащий программе движок и восстанавливает маршруты. Выход из программы делает то же самое; сворачивание сохраняет подключение. Windows Job Object завершает дочерние процессы, если основная программа аварийно закрылась. Для запуска, проверок и остановки заданы сроки ожидания и принудительное завершение при необходимости. Если недоступен только сервер прокси, выбранные приложения остаются на его маршруте, остальные продолжают работать через провайдера. Если остановился сам движок, туннель выключается и все приложения возвращаются к провайдеру. При проверке маршрутов не запускайте одновременно ProxyFlow, другой TUN VPN и ProxyChoicePro.

## 8. Скорость, мегабайты и журнал

Карточка состояния показывает приём, отправку и скорость последнего замера. Счётчики относятся к текущему сеансу туннеля и включают прямые и прокси-соединения, обработанные движком; это не отдельный счётчик оплаты у поставщика прокси. МБ рассчитывается как 1 048 576 байт. Применение правил создаёт новый сеанс и обнуляет счётчики. Вкладка «Журнал» содержит события приложения и последние записи движка. «Очистить» убирает текущие записи из окна и экспорта; новые записи появляются как обычно. Файл движка остаётся открытым до отключения, после чего удаляется. «Сохранить» экспортирует видимый журнал со скрытыми данными авторизации. Адреса сайтов и пути приложений могут оставаться в журнале.

## 9. Если что-то не работает

Проверьте тип прокси, адрес, порт, логин и пароль, затем нажмите «Проверить прокси». Если приложение показывает старый IP, проверьте точный путь к .exe, примените выбор и перезапустите его. Лаунчеры и дочерние программы могут требовать отдельных записей. Если процесс недоступен для просмотра, добавьте его через «Выбрать .exe». Программа предназначена для Windows 10/11 x64 и содержит среду выполнения и движок; устанавливать .NET отдельно не нужно. Установщик создаёт ярлыки и программу удаления; отдельный EXE запускается без установки. Данные находятся в %LOCALAPPDATA%\ProxyChoicePro. Автор: Alexander Savinskiy, a.savinskiy@gmail.com. ## 10. Рабочая сеть

Импортируйте клиентский файл WireGuard .conf, созданный для этого компьютера. Профиль содержит ключи доступа, адрес клиента VPN, сервер и разрешённые сети. Сохраните его один раз, затем нажимайте «Подключить». Рабочие маршруты действуют для всех приложений, включая удалённый рабочий стол Windows. Остальной интернет использует обычное соединение. Если в профиле AllowedIPs=0.0.0.0/0, укажите конкретные рабочие подсети и доступный TCP-сервис для проверки в настройках профиля. Скрипты и несколько пиров не поддерживаются. DNS из файла не устанавливается; используйте IP рабочих ПК.

## 11. Рабочие компьютеры и RDP

Добавьте название, IPv4/IPv6-адрес и TCP-порт рабочего ПК. Стандартный порт RDP — 3389. Имя пользователя необязательно; пароль запрашивает клиент удалённого рабочего стола Windows, в файл .rdp он не записывается. Подключите рабочий профиль, выберите ПК и нажмите «Открыть рабочий стол». IP должен входить в рабочие маршруты. Рабочий ПК должен быть включён, поддерживать входящий RDP и разрешать клиенту VPN доступ через брандмауэр. Проверка RDP подтверждает доступность TCP-порта, а не пароль или вход в сеанс Windows.

## 12. Диагностика, восстановление и ночной режим

Диагностика отдельно проверяет движок, доступ через зашифрованный рабочий туннель, выбранную службу RDP и пересечение рабочих и локальных подсетей. Работа движка сама по себе не подтверждает доступ к рабочей сети. После двух неудачных проверок или выхода из сна автоматическое восстановление повторяет попытки через 5, 10, 20, 40 и затем 60 секунд. «Отключить» или «Остановить переподключение» отменяет повторы. Зелёный значок означает подтверждённый доступ, серый — отключение, жёлтый — подключение, красный — ошибку доступа. Ночной режим и язык сохраняются. В узком окне вкладки переносятся, форма подключения располагается вертикально.

## 13. Список приложений и готовые профили

Во вкладке «Приложения» есть Chrome, Edge, установленные браузеры, ChatGPT, Codex и codex-computer-use-swift. Отсутствующие программы показаны как недоступные. Запись Codex объединяет найденные исполняемые файлы настольного приложения, командной строки и режима кода. У записей с общим исполняемым файлом выбор связан. Для Microsoft Store есть отдельная галочка. Этот выбор действует в режиме «Прокси»; рабочие маршруты действуют для всех программ.

Готовый клиентский файл может содержать комментарии ниже. Routes задаёт рабочие адреса, ProbeHost и ProbePort — доступную TCP-службу для проверки. Импорт проверяет их соответствие AllowedIPs. Обычный клиент WireGuard игнорирует эти комментарии.

```ini
# ProxyChoicePro.Routes = REPLACE_WITH_WORK_ROUTES_CIDR
# ProxyChoicePro.ProbeHost = REPLACE_WITH_WORK_TCP_SERVICE_IP
# ProxyChoicePro.ProbePort = REPLACE_WITH_WORK_TCP_SERVICE_PORT
```
